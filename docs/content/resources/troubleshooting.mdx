# Troubleshooting

Start with the installed version and selected paths:

```bash
codai --version
codai config paths
codai config model
```

Configuration inspection omits credential values and does not start external tools.
Review any report before sharing it; do not include configuration secrets or tokens.

## Setup keeps opening

Later runs should reuse a valid saved connection. Check that you are using the
same configuration scope and that a project file is not taking precedence over
user-wide defaults.

An unconfigured run still onboards even when environment variables provide credentials.
For an existing configuration, a provider that requires a credential needs either
an API key or an account reference. Use `codai auth` to repair the saved connection.

## Model selection fails

1. Check provider and endpoint with `codai config model`.
2. Retry discovery or enter a custom ID in `codai auth`.
3. Use your Azure deployment ID, not a public model name.
4. For Ollama, verify the model is installed on the selected server.
5. Check [transport compatibility](/providers/models#compatibility-boundaries).

Suggested models do not verify account access. A model appearing in discovery does
not prove support for multi-turn coding tools.

## Saved settings do not take effect

Environment variables and flags override saved values. Inspect settings and paths
before saving repeatedly. Provider, default model, and integration changes generally
apply at next startup.

**Theme** is applied after a successful Save. Cancel and failed saves leave the active
theme unchanged. The session-only model selector is different: Enter applies it
immediately, without changing saved defaults.

## Files or commands are refused

| Check | What to do |
| --- | --- |
| Plan mode | Switch to Agent only when you intend to change the project |
| Shell disabled | Restart without `--no-shell` when command access is intended |
| Tool explicitly disabled | Inspect `disabled_tools` and `--disable-tool` |
| One-shot or piped task | Approval input is unavailable; writes are denied by default |
| File unreadable/oversized | Narrow the task; do not bypass the read-before-write requirement |

<Callout type="warning">
  Do not enable automatic approval merely to suppress an unexplained refusal.
  Identify the capability or policy responsible first.
</Callout>

## A key does something unexpected

- Ctrl+M may arrive as Enter. Use Ctrl+P or F1 for settings.
- Tab accepts a visible completion before it toggles mode.
- Hold Shift for terminal text selection when mouse reporting intercepts dragging.
- Mode/approval shortcuts do not change state while answering a confirmation.

See [Terminal and shortcuts](/usage/terminal) for expected behavior.

## Streaming or output looks stuck

Streaming needs provider support and `stream: true`. Early responses do not
display elapsed time or output-token counters until two seconds have passed.
Reasoning steps display status, not private reasoning.

Escape stops the current request while keeping the session open. It does not roll
back file changes. Inspect the transcript and working tree before trying again.

## Saved work seems missing

Check the project root and `--data-dir`. Use `:session history` or `:task history`
to locate saved work. Continuing a chat does not restore checkpoint files.
See [Sessions and recovery](/usage/sessions) before restoring anything.

## MCP or plugin changes are not active

Before the first model request, interactive sessions re-read MCP definitions and
selections. After connections initialize, changes require a restart; inspection
does not reload live tools. Newly installed plugin skills and commands can be
used immediately, while native .NET code and initialized MCP connections need restart.
Check the configured name/path, enabled state, transport, and timeout.
See [MCP](/mcp) or [Plugins](/plugins). Never mark an unknown remote tool read-only
just to make it available in Plan.

## Icons appear as squares

Select a Nerd Font in your terminal, or set `CODAI_ICONS=unicode` before launching
Codai. Codai cannot reliably detect the selected font. Nerd Font action icons are
white; error message text stays red. See [icons and fonts](/usage/terminal#icons-and-fonts).

## Tabs or mouse feedback look wrong

Tab hover changes text only; it has no animation. Current builds hide the cursor
while painting and preserve the tab strip during switches. If an installed older
build flashes a block over a tab, check `codai --version`, run `/update` where
supported, and restart. Mouse motion and click forwarding depend on the terminal;
use `/session next`, `/session previous`, or the keyboard shortcuts when intercepted.

## Update cannot install

`/update` checks stable nuget.org releases. Automatic installation needs the .NET
10 SDK and the running tool's global or custom `--tool-path` installation. Source,
local-manifest, and standalone builds are check-only; update them through their
original method. Update consent is explicit even with Auto approval. Network,
SDK, timeout, or permission failures do not imply success. Restart after a
successful installation. See [update requirements](/usage/terminal#updates).

## A lifecycle hook blocks work

Inspect `codai config hooks` and the reported manifest/command. Matching command
hooks need Agent mode, shell access, and approval; malformed manifests or output
fail closed. Use `--no-hooks` only after deciding those hooks should not run, not
as an unexplained policy bypass. See [lifecycle hooks](/customization/hooks).

## Report a reproducible issue

Use `:report-bug <summary>` to save a local diagnostic report under `.codai/reports`
after confirmation. Include the version, exact command, expected behavior, and
smallest safe reproduction when filing an issue.
Reports are local; creating one does not automatically publish it.
