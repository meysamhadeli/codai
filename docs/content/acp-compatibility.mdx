# ACP compatibility

Use this adapter when building an editor or host integration around Codai.
For terminal scripting, use the [CLI's JSON output](/resources/cli) instead.

<Callout type="warning">
  This is a compatibility subset, not a complete Agent Client Protocol implementation.
  Do not assume compatibility with an arbitrary ACP client.
</Callout>

## Start the adapter

Codai includes a host-neutral stdin/stdout JSON-lines host. Start it with:

```text
codai --acp
```

Send one JSON object per line to stdin and read one JSON object per line from stdout.
The adapter is optional and does not change the normal `codai code` or `codai --json`
behavior.

## Messages

Create or resume a session:

```json
{"type":"new_session","sessionId":"demo","cwd":"C:/work","provider":"ollama","model":"qwen","mode":"plan","resume":true}
```

Then send a prompt:

```json
{"type":"prompt","sessionId":"demo","text":"Inspect the project"}
```

| Message | Purpose |
| --- | --- |
| `initialize` | Initialize the compatibility host |
| `new_session` | Create or resume a session with selected settings |
| `prompt` | Submit work to a session |
| `set_mode` | Change Plan / Agent policy |
| `cancel` | Cancel active work |
| `permission_response` | Respond to a permission request |

Events include `session_created`, `mode_changed`, `permission_request`, `progress`,
`text`, `usage`, `prompt_complete`, and structured `error` objects.

Session modes are `plan` and `agent` (the default). Both `new_session` and `set_mode`
reject the removed `ask` mode.

## Compatibility boundary

This adapter is not the complete Agent Client Protocol. It does not implement JSON-RPC
request IDs, capability negotiation, authentication, binary/image content, separate ACP
terminal resources, or changing provider/model in an existing session. Create another
session when provider or model selection changes. The application layer still owns
configuration, permission policy, cancellation, and session/task persistence.

## Integration checklist

<Steps>

### Keep the channel structured

Write one JSON object per line and parse stdout as events, not human-readable
terminal output. Associate work with the intended session ID.

### Handle permission requests

Surface requests to the user rather than assuming consent. Model and mode choices
do not remove application-layer policy.

### Handle completion and cancellation

Process `prompt_complete` and structured errors. A cancellation is not a rollback
of files already written.

### Recreate sessions for connection changes

Start another session when changing provider/model. This adapter does not mutate
an existing session's connection.

</Steps>

See [Permissions](/usage/permissions) and [Sessions and recovery](/usage/sessions)
for behavior shared with the terminal host.
