# VS Code extension roadmap

Codai's next product direction is a native VS Code extension: one place to discuss
changes, plan work, edit code, run tools, and review results inside the editor.
The extension will reuse Codai's host-neutral runtime and existing provider, skill,
MCP, permission, and task capabilities rather than maintain a separate agent engine.

<Callout type="info">
	This page contains planned extension work only. It does not announce a released
	extension or imply that the editor features below are available today. Current
	capabilities remain documented in their individual guides. Phases indicate
	delivery order, not release dates.
</Callout>

## Phase 1: Extension Foundation

- Add a Codai Activity Bar entry, sidebar conversation view, command palette actions,
	and status indicators that respect VS Code themes, keyboard navigation, and accessibility.
- Connect the extension to the shared runtime with versioned messages, streamed
	responses, progress events, questions, tool approvals, cancellation, and clean shutdown.
- Provide provider onboarding, model selection, connection checks, and credentials
	stored through VS Code SecretStorage rather than committed workspace settings.
- Support explicit Plan and Agent controls, separate model profiles, and a reviewed
	transition from a plan to execution.
- Respect Workspace Trust before reading project guidance or starting external tools;
	keep workspace trust, connection approval, and tool-call approval separate.

**Acceptance:** A user can connect a provider, start a task in the sidebar, inspect
its plan, approve an action, receive streamed results, and cancel without leaving
or blocking the editor. Reloading the window does not silently grant consent.

## Phase 2: Contextual Coding And Review

- Attach selections, open files, folders, diagnostics, terminal output, and Git diffs
	through editor actions and searchable context mentions.
- Read unsaved editor buffers accurately, bound attached context, respect exclusions,
	and isolate settings and permissions across multi-root workspaces.
- Add explain, review, refactor, fix-diagnostic, and generate-test actions near selected
	code and in editor context menus.
- Let the agent search, create, edit, rename, and delete workspace files through
	controlled tools, with native diff previews and file/hunk accept or reject actions.
- Detect edits made during a task, preserve unsaved user changes, and require fresh
	review when a proposed edit no longer matches the current document.
- Turn diagnostics and focused test results into a bounded edit-and-validate workflow.

**Acceptance:** A task can use real editor context, propose a multi-file change,
apply only approved edits, and report validation. User changes are never overwritten
silently, and Plan mode cannot mutate files or launch commands.

## Phase 3: Integrated Agent Tools

- Run approved commands in integrated terminals with streamed output, background
	process visibility, cancellation, and ownership-aware process cleanup.
- Add isolated browser automation for approved web workflows: navigation, screenshots,
	page interaction, and console/network evidence for debugging and verification.
- Support image and screenshot attachments for compatible models, with clear
	capability checks and control over data sent outside the workspace.
- Provide MCP server management for stdio and HTTP, source inspection, connection
	review, authentication, tool/resource/prompt browsing, and connection-health reporting.
- Add controlled MCP reconnect and configuration refresh without restarting VS Code;
	changed server definitions must invalidate prior approval.
- Surface per-action approval, optional scoped auto-approval, timeouts, and tool budgets
	consistently for file, terminal, browser, and external tools.

**Acceptance:** Tool activity and results are visible in the conversation, risky
actions require the configured consent, cancellation reaches owned processes, and
external tools cannot bypass mode or workspace permissions.

## Phase 4: Skills And Workspace Customization

- Manage global, project, and additional skill roots in an editor-native view with
	source labels, descriptions, search, and automatic-activation controls.
- Keep manual skill commands separate from automatic checks, expose invocation/path
	metadata, and refresh discovered skills when relevant workspace context changes.
- Bring project instructions, conditional rules, memory, reusable commands, and
	`.codai.json` runtime and discovery settings into an editor-native configuration experience.
- Offer user/workspace provider profiles, per-mode models, and explicit effective-value
	inspection without exposing credentials or silently changing active connections.
- Integrate trusted hooks and extensions through the shared runtime while keeping
	project-supplied code and external services behind explicit trust boundaries.

**Acceptance:** A user can inspect why guidance or a tool is active, configure its
scope, and apply changes predictably. Manual invocation never changes automatic
skill selection or grants tool permissions.

## Phase 5: Long-Running Tasks And Recovery

- Add task history, search, resume, task switching, and versioned export/import from
	the sidebar without mixing conversations or workspace roots.
- Expose task steps, context usage, compaction, token/cost estimates, and configurable
	budgets with pause, cancel, retry, and follow-up controls.
- Provide checkpoint timelines, changed-file comparisons, and explicit restoration
	with clear handling of binary files, deletions, and concurrent user changes.
- Surface bounded background specialists and teams with progress, results, separate
	budgets, and read-only delegation by default.
- Recover from editor reloads, provider failures, and interrupted tool calls without
	repeating completed mutations or automatically widening consent.

**Acceptance:** An interrupted task is inspectable and resumable. Restoration is
separate from conversation resume, requires confirmation, and leaves the user's
Git history and index untouched.

## Phase 6: Distribution And Release Quality

- Publish a versioned VSIX and VS Code Marketplace listing with install/update guidance,
	runtime compatibility checks, release notes, and an offline installation path.
- Validate Windows, macOS, and Linux, multi-root workspaces, and remote development
	environments, including SSH, WSL, and Dev Containers.
- Test extension/runtime communication, webview security, credentials, approvals,
	editor-buffer conflicts, process lifecycle, and reconnect/recovery behavior.
- Ship keyboard-accessible, theme-aware views and diagnostics that omit secrets.
	Keep telemetry optional and document what leaves the machine.
- Document editor workflows and settings alongside each delivered feature; label
	unsupported environments and capabilities rather than implying support.

**Acceptance:** The extension installs and updates predictably, passes the shared
runtime and editor integration gates, and publishes an accurate supported-feature
and environment matrix.

## Release Criteria

- Every feature includes focused tests plus an editor/runtime integration check.
- Read-only modes and approval boundaries remain fail-closed at execution time.
- Persistent task data is versioned; secrets stay outside source-controlled settings.
- Runtime builds remain warning-free, and extension type checks, tests, packaging,
	and documentation validation pass before release.
- No extension capability is marked available until implemented and verified.
